## 位置づけ

### 試遊フィードバックの反映

粒子のタップ/クリック判定半径を26から36 logical px（約1.38倍）へ拡大。Dailyと訓練の共通判定へ反映。粒子ルールv2として保存し、v1で開始済みの試験は従来の判定を維持する。訓練の自己ベストと平均もルールバージョンごとに分ける。

v0.1.0 / 初回MVPのローカル検証版。空の指定リポジトリにVanilla JS ES Modules + Canvas + 小規模サーバーを構築。新規ブランチは `yuzora/mvp-foundation`。
ユーザー指定リポジトリ・既存の配信方式を維持するため、別のSitesプロジェクトや別フレームワークへ移行していません。

## 保存とセキュリティ

- Cookieには256-bitランダムトークン、DBにはSHA-256ハッシュのみを保存。HTTPSではSecureを付ける。
- mutationはsame-origin、専用ヘッダー、JSONサイズ上限、型・所有チェックを行う。
- D1 `players` のrevision比較更新と `operations` の冪等レシートを同一batchで保存。競合時は409、同じキーの再送は既存結果を返す。
- カードの未回答正解はbootstrap、start、playerに含めない。粒子の結果はサーバーで座標・時刻から再計算。
- 途中離脱と低FPSは結果を破棄して再挑戦可能。クライアントを解析する上級者への完全なアンチチートではない。
- Dailyは同日/testの完了を保持、04:00跨ぎの古い未完attemptは失効。Trainingはサーバー報酬APIを呼ばない。
- 戦闘回数は開始時に消費。結果はサーバーが生成し、finishはその結果だけを精算。画面を閉じてもロビーから再開できる。
- 予測/レイドのAPI、AIキー、ユーザーアクセス時AI呼び出しは存在しない。
- ゲストの大量作成に対する本番レート制限、運用バックアップ方針、ログ保持期限の設計は公開前の残課題。
- プレイヤーごとのJSONは簡潔な初期設計。長期運用では履歴を別テーブルへ移行しページングする必要がある。

## 占術と分析

初期研究値は全軸15、XPから単調増加し上限100。日次コンディションは当日XPから0〜10に制限。
キャラ適性は独立した新作オリジナル値。星座は日付境界の簡易表、数秘は桁和、5軸は娯楽用の固定ルールであり、天文学的計算や能力診断ではない。
出生情報はlocalStorageだけに保存し削除可能。サーバーへの送信がないことをブラウザテストで確認する。

## 既知の制約

- 本番公開・クラウドDB作成・Git pushは未実施。ローカルURLのみ提供。
- Cookie消失後の復元・アカウント同期は未実装。エクスポートJSONは閲覧用で、改ざんしたRCを復元できるインポート機能は設けていない。
- 対応端末はまずEdgeで確認。実機の画面性能・Safariの挙動・高齢ユーザー等への可読性は追加確認が必要。
- 音源、素材一括プリキャッシュ、Service Workerは導入していない。画像は必要時に取得する。
- XP曲線・戦闘基礎式は新作用。PRISMA ABYSSの戦闘・成長との完全互換を主張しない。
